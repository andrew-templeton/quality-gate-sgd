# Quality Gate Configuration

> Generated by `quality-gate-sgd init`

## Overview

This project uses deterministic quality gates to create consistent improvement
pressure on code quality. The gates are calibrated to your current metrics,
ensuring you can pass immediately while requiring monotonic improvement.

## Quality Dimensions

| Dimension | Current | Floor/Ceiling | Monotonic |
|-----------|---------|---------------|-----------|
| TypeScript Errors | 0 | ≤0 | ↓ |
| ESLint Errors | 0 | ≤0 | ↓ |

## How It Works

1. **Floors**: Minimum acceptable values (coverage must stay above)
2. **Ceilings**: Maximum acceptable values (errors must stay below)
3. **Monotonic**: Values can only improve, never regress

The monotonic rules create a "ratchet" effect: once quality improves,
it cannot go back. This creates consistent descent toward higher quality.

## Usage

```bash
# Run quality gate
npx quality-gate-sgd

# View trajectory (after multiple runs)
npx quality-gate-sgd trajectory
```

## Theory

This system is based on the principle that deterministic quality gates
create gradient descent-like behavior from stochastic agents (like LLMs).
See the [quality-gate-sgd documentation](https://github.com/your-org/quality-gate-sgd)
for the theoretical foundation.
