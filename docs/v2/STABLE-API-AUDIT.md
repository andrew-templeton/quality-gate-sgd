# Combined contract acceptance audit

This audit revisits the three stabilization requirements in [API-REVIEW.md](API-REVIEW.md) against the contracts introduced in `2.0.0-dev.2` and consolidated for `2.0.0-dev.3`, public declaration fixtures, actual crash/recovery tests and independently installed module checks. It concerns the reusable protocol and execution controls. Audience comprehension, semantic-verifier accuracy, operator preference and composition utility require their own evidence.

The original identity, executable-input and local-durability gaps have concrete implementations and corresponding acceptance evidence. The core keeps its development version while the final integrated build, public package checks and release records are completed. Closing the minimum API review does not close the rest of the work graph or qualify every assertion in its catalog.

## Original acceptance mapping

| Original requirement | Implementation and direct evidence | Boundary retained |
| --- | --- | --- |
| An independent module declares protocol, implementation and semantic configuration without opaque version-string conventions | `AssertionContract`, `defineAssertion`, `evaluatorIdentity`; independently installed Isogloss, SonarQube and software modules | Producer-declared code and dependency identity is not execution attestation |
| Relevant rubric, threshold, audience, prompt/model or implementation changes invalidate comparison identity | Contract identity includes implementation, configuration, applicability, statement and input/output bindings; `contracts.test.ts` changes each semantic field; admission and durable opening reject changed identities | A caller must explicitly include all behaviorally relevant settings and dependencies |
| Caller mutation cannot alter the compiled declared configuration | Frozen copied configuration, cards, input descriptors and captured callback; nested configuration and instance-owner regressions in `contracts.test.ts`; receiver preservation in `api-consumer.test.ts` | A JavaScript closure or external service can violate its declaration; the engine does not sandbox or authenticate verifier code |
| Irrelevant metadata differs from semantic identity | Canonical JSON key order is tested; display-title edits preserve evaluator identity while the encompassing gate digest records the edit | A changed full gate still requires a new comparison baseline, even where a semantic qualification can remain applicable |
| Qualification names current evaluator and scope | Compiler requires current `evaluatorDigest` and `applicabilityDigest`; semantic mutations reject the old record; external conformance repeats this boundary | Replacing a hash does not make old empirical evidence applicable |
| Public typed input authoring without internal imports or repeated payload casts | `bindInput`, the bounded `schema` algebra and `defineAssertion` deliver typed values; `tests/public-contract-types.ts` verifies emitted declarations and negative type cases; installed modules use public contracts | `schema.json()` deliberately yields unknown JSON; the algebra is not JSON Schema |
| Missing, incompatible or malformed input is unavailable before dependent paid dispatch | `evaluateGate` preflights `prepareInput`; missing path/property, wrong type, extra fields, absent capability and schema-version cases assert zero dispatch and cost | Envelope misuse can be a rejected API call; shape-valid but stale or incomplete evidence is an evaluator obligation |
| Required values and alternatives are unambiguous | One named/versioned binding per assertion; object schemas hold multiple required values and unions express explicit alternative shapes; all declared capabilities are required | No implicit coercion, version fallback or semantic equivalence |
| Discovery and execution share compatibility rules | `discoverAssertions` uses `inputCompatibility`; workflow planning adds exact schema/path checks, runtime sample validation and `compileGate` closure checks; `contracts.test.ts` and `workflows.test.ts` compare actual runtime behavior | A declaration match is a candidate for inspection; a validated sample is not a passing quality assessment |
| Independent composition covers valid, invalid, version-mismatched and prerequisite-blocked cases | Separate package installs and public exports in [EXTERNAL-CONFORMANCE.md](EXTERNAL-CONFORMANCE.md), including Isogloss and SonarQube | Domain implementations remain outside core and protocol conformance makes no new domain-validity claim |
| Checkpoint preserves identity, admitted state, history, counters, attempted candidates and accounting | Versioned `DurableRunState` plus `LoopCheckpoint`; restored settings bind gate, environment, runtime declarations and proposal/repair/workspace identities | Explicit rebaselining starts a comparison epoch while retaining prior history and expenditure |
| Reservations and uncertain operations cannot silently reset or repeat | Stable run/epoch/request IDs; prepared/dispatched/completed operation states; retained unknown reservations, reconciliation and conservative abandonment | Unknown external work requires evidence or a conservative charge; timeout/cancellation cannot prove remote non-execution |
| Restore validates integrity and chronological consistency | Journal checksum/version and ordered events; restored ledger recomputes spend and settlement order; loop validates admitted/attempted identities, history, stalls and current evaluation inputs | Checksums detect accidental corruption, not malicious rewriting or rollback of an entire run directory |
| Actual interruptions cover paid-work and admission boundaries | `durable-loop.test.ts` kills separate Node processes around reservations, dispatch, outcome recording, settlement, candidate creation/evaluation and admission; recovered fixture receipts prevent duplicate repairs | This demonstrates the specified process-crash boundaries, not arbitrary host loss or distributed transaction atomicity |
| Writer scope and resumed control behavior are explicit | Exclusive local writer ownership, fsync/rename boundary, dead-PID recovery and poisoned failed writer; six-round independent fsynced receipt ledger verifies evaluations/tokens/cents/rounds, deadband, cooldown and hard nonregression; resumed cycle/stall/budget cases | One writer on a local POSIX filesystem with the documented persistence operations; no concurrent/distributed worker guarantee |

## Additional public composition boundaries

Typed outputs extend prerequisite ordering into actual data handoffs. Compilation checks explicit producer prerequisites and exact output schema definitions/versions. The host creates each receipt from a passing validated output, binding producer identity, current evaluation input, schema, value and upstream receipt digests. A runner's invented receipt cannot replace it, and unavailable or failed producers cannot supply evidence. [EVIDENCE-HANDOFFS.md](EVIDENCE-HANDOFFS.md), [outputs.test.ts](../../tests/v2/outputs.test.ts) and the public type fixture cover those contracts and durable replay. Downstream qualification still needs reassessment when a changed producer changes the input distribution.

[Assertion context](ASSERTION-CONTEXT.md) exposes the exact selected subset: machine-readable family hierarchy, claims, assumptions, exclusions, applicability, configuration, evidence requirements, qualification and costs. The composed card retains individual boundaries without multiplying pass rates or inventing a confidence score. The business-reader example includes required obligations and optional Isogloss language diagnostics. Context and resource tests verify vocabulary and selected-card consistency; discovery does not install modules or authorize harnesses.

[Workflow planning](WORKFLOWS.md) accepts explicit application input/output ports, locally supplied modules and required/optional requirements. It enumerates a bounded set of alternatives, preserving match reasons, omitted optional facets, unsupported requirements, missing schemas/capabilities, prerequisite order, typed handoffs and one-evaluation cost bounds. Family/text matches remain descriptive hints. Neither configuration nor qualification changes during planning, and no evaluator or remediation runs. The installed fixture successfully executes a broader arithmetic-plus-Isogloss composition and an external software composition. Planning and execution are separate operations with separate authority and budgets.

[Evidence lineage](LINEAGE.md) adds shared addresses and transitive source/asset/render/audience/policy/evaluator dependencies. A child CSS edit with an unchanged parent file invalidates dependent evidence while an independent arithmetic branch can reuse a matching receipt. Missing/cyclic graphs and stale receipts fail closed; selected lineage roots can supply durable environment identity. These hashes bind declared dependency coverage supplied by collectors. They do not prove that the collector observed every relevant dependency or that a newly sealed receipt represents a newly collected observation.

## Findings from this combined review

| Finding | Disposition and evidence |
| --- | --- |
| A self-consistent output receipt could carry unsupported fields or non-SHA identity/dependency strings | Fixed with exact envelope fields and SHA-256 validation; `outputs.test.ts` rejects self-consistent malformed receipts |
| A workflow sample with an empty artifact ID, artifact digest or environment digest could be labeled `validated-inputs`, then fail `evaluateGate` envelope validation | Fixed by matching the runtime identity-field validation before sample binding; all three cases now produce `incomplete`/`runtime-input-invalid`, with no evaluator dispatch or spending; all 13 workflow tests pass |
| A present `output: null` or `prerequisites: null` descriptor could bypass optional-field validation and be omitted from evaluator identity | Fixed by own-property presence checks in descriptor identity, validation and `defineAssertion`; null and explicit undefined are rejected; the combined 30 contract, 10 output and 13 workflow tests pass |
| The installed software collector could report changed inputs solely because mixed relative/absolute paths were sorted differently | Fixed and publicly pushed in software [13308ba](https://github.com/andrew-templeton/quality-sgd-software/commit/13308ba), version `0.1.0-dev.2`; original failure retained in its validation record; 20 collector tests, installed real ESLint layout regression, host conformance and the actual installed repair workflow pass |

The original installed host artifact was `quality-gate-sgd@2.0.0-dev.2`, SHA-256 `68884f3a9262bdb7fd3cb1d7bb2a0fd1f44b2d84d7e4b304e225a137f5c3b346`. It predates the final sample-envelope and optional-field refinements. The final integrated validation must identify the rebuilt artifact rather than presenting this earlier hash as evidence for later code.

## Compatibility and versioning scope

The consolidated source release remains `2.0.0-dev.3`; it is not an npm registry publication or a promise to freeze every newly added helper. The review supports a defined interoperability boundary with explicit versioned data. Consumers should pin the reviewed public source revision or package artifact and run its module conformance fixtures before updating.

| Boundary | Compatibility policy |
| --- | --- |
| Public imports | Direct named exports and the `v2` namespace from `quality-gate-sgd` are the tested host entry points. Module authors can instead supply structurally conforming descriptors without a core runtime dependency. Internal source imports are unnecessary. |
| Assertion descriptor | `quality-sgd.assertion/v1` specifies explicit implementation/configuration/applicability identity and executable input binding, with optional typed outputs and named prerequisites. Unknown protocols and unsupported descriptor/schema fields are rejected. Absent optional fields are omitted; explicit null/undefined is not a substitute. Conforming descriptors that omit handoffs retain their prior identity representation. |
| Input and output schemas | Schema ID, version and exact supported definition identify a binding. Multiple required values and alternatives remain explicit. A changed shape or meaning needs an intentionally versioned schema and module review; compatibility is not inferred from matching prose or family names. |
| Evaluator and gate identity | Any behaviorally relevant implementation, configuration, applicability or statement change creates a new evaluator identity. Qualification must refer to the current evaluator and scope. Changed full gate/environment identity requires explicit rebaselining; old accounting survives. Display metadata can alter the containing gate while leaving the semantic evaluator unchanged. |
| Durable storage | The current journal, loop checkpoint and ledger have explicit versions and a local single-writer POSIX scope. Unsupported versions and incompatible runtime settings are rejected. There is no silent checkpoint upgrade, budget reset, concurrent-worker guarantee or distributed transaction contract. |
| Workflow/context/lineage helpers | These dev.3 additions produce inspectable versioned records and use the enforcement boundary above. A proposal, context card or lineage receipt does not qualify a verifier, prove authentic collection or authorize execution. Their documented behavior and fixtures apply to the pinned development artifact. |
| External modules | Isogloss, software and SonarQube keep independent package/source versions, cards, implementation identities and domain evidence. Core has no runtime domain dependency. Protocol compatibility and domain validity are separate assertions, and each package states its own supported runtime/tool versions. |
| Legacy migration | Legacy assertions require explicit compiler opt-in and are marked in composed cards. The old software exports/CLI remain owned by the software package. No legacy aggregate pass gains the stronger input, identity or complete-evidence guarantees implicitly. |

The tested CI targets and actual local command environment belong in the release validation record. An engine-range declaration alone is not evidence that every Node release, operating system or filesystem has passed the crash and package fixtures. New protocol or storage versions require explicit migration documentation and fresh conformance evidence; development package version increments alone do not authorize reuse of old qualification or comparison history.

## Graph closure recommendations

The existing evidence supports the completed `implementation-identity`, `qualification-invalidation`, `input-bindings`, `discovery-consistency`, `durable-ledger`, `checkpoint-resume`, `crash-idempotency`, `loop-costing-hysteresis` and `typed-prerequisite-outputs` tasks within their unchanged criteria. The external installed records support `external-conformance`. Context, lineage and workflow implementation/tests support their corresponding tasks when their final integrated code, public docs and artifact checks are recorded. No human study is needed to establish those specific protocol behaviors.

Both strict-contract findings above are resolved in source with passing focused regressions. `stable-api-review` can close when the rebuilt dev.3 host passes required integrated checks and this combined review plus current versioning, migration and execution-scope documentation are published with prerequisite evidence. Retain precise source/tarball versions for external modules: public Git publication and npm registry release are separate events. During development, pin a reviewed source revision/package artifact; behavioral contract changes require recompilation and explicit rebaselining. Legacy assertions remain a deliberate compiler opt-in with weaker identity/input guarantees.

This closure does not establish `audience-calibration`, empirical semantic `verifier-calibration`, `composition-calibration`, or the full public end-to-end milestone by itself. A deterministic arithmetic predicate, a report completeness check, a lexical counter, a model judgment and an observed reader outcome support different conclusions. Retain unqualified or incomplete labels wherever the evidence for the intended application is missing.
